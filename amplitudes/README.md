# Amplitude tables (driver outputs of the NNLO BχPT code)

Every fit of the paper uses the Compton observables only through these tables: for each kinematical point the
NNLO BχPT amplitude is tabulated as an exact quadratic form in the six static dipole polarizabilities, so that any
fit, any variation of the polarizabilities and any order-by-order comparison can be done without running the
Fortran code.  The tables were produced by `code/code_v2/execs/ampl.exe` in its fit-driver mode (`&fitdriver`
namelist, see `code/code_v2/driver/README.md`), called through `code/fits/lib/bchpt.py`.

## Files

`<name>_<key>.out` with the sidecar `<name>_<key>.out.json`.

* `name` = `<tag>_<configuration>`: the point set (tag) and the configuration of the amplitude.  Tags: `db` = the
  624 points of `data/fitdb.csv`; `dbpb` = the 720 points of `data/fitdb_pb.csv` (A2 per beam time); `pref` = one
  point, used only to read the reference polarizabilities; `val_fwd_*` = the θ = 0 validation points;
  `fig_*`, `grid_*`, `pred_S2_*`, `fig_pred_ratio_*` = the curves of the figures; `sigtot_*` = the (E, cos θ_cm)
  grid of the total cross section (`code/sigma_tot`); `t6_*` = test points of the order-switch checks.
* configuration (`code/fits/lib/bchpt.py`, `CONFIGS`): `NNLO` = the full amplitude of the paper (Born, π0 pole,
  πN loops with physical pion and neutron masses, Δ pole and πΔ loops with the γNΔ vertex corrections);
  `NLO` = O(p³) (order switch `order=3`: Born with anomalous magnetic moments, π0 pole, πN loops); `BornPi0` =
  Born and π0 pole only (reference amplitude of the truncation estimate); `LO` = O(p²) Born; `NNLO_noPiD`,
  `NNLO_noDpole` = diagnostics; `gM<value>` = γNΔ coupling g_M varied (`...nv` = without vertex corrections);
  `PDG24`, `PDGconst` = PDG-2024 constants; `hA2.84`, `hA2.91` = πNΔ coupling varied; `singlemass` = one pion
  mass in the loops; `novtx` = without γNΔ vertex corrections.
* `key` = the first 16 hex digits of sha1(points text + in.dat + baryon.dat), i.e. of the complete driver input.
  The sidecar stores that input (`inputs.in_dat`, `inputs.baryon_dat`), the configuration dictionary, the
  executable used (path, size, mtime) and the code version (`code_id`, the git commit of `code/code_v2`).

## Format of a table

Header lines start with `#` and give the reference polarizabilities `Pref` (the static polarizabilities of the
configuration, at which the tabulated amplitude is evaluated), the analytic NNLO values with their πN / Δ-pole /
πΔ breakdown, `Puser`, flags and constants.  Then one line per point:

```
id  obs  E_lab[MeV]  theta_lab[deg]  theta_cm[deg]  value(Puser)  flag  c_num[28]  c_den[28]
```

The observable at polarizabilities P is the exact ratio of two quadratic forms in the shifts d_k = P_k − Pref_k:

```
O(P) = N(d) / D(d),    N(d) = Σ_{a≤b} c_num[ab] d_a d_b,  d_0 = 1,
(a,b) ordered (0,0),(0,1),...,(0,6),(1,1),(1,2),...,(6,6)      [28 coefficients each]
P = (α_E1, β_M1 [1e-4 fm^3];  γ_E1E1, γ_M1M1, γ_E1M2, γ_M1E2 [1e-4 fm^4])
```

For the cross sections (`CS` lab, `CSCM` c.m., `SPAR`, `SPERP`: nb/sr) D ≡ 1; for the asymmetries (`S3`, `S2X`,
`S2Z`) D is the unpolarized cross section.  `flag` = 1 marks points near 0° or 180° where the loop amplitudes were
extrapolated in t, `flag` = 2 points below 15 MeV where the loops are replaced by their static form.  The Python
reader is `code/fits/lib/bchpt.py`, class `DriverOutput` (`predict_array(P)` evaluates all points for a parameter
set with two matrix products); `code/code_v2/driver/compton_qf.py` is a stand-alone reader with a minimal fit.

## Regenerating the tables

Build `ampl.exe` (README.md, Sec. "Rebuilding the amplitude tables"), delete the tables to be recomputed (or the
whole directory) and run the pipeline; `bchpt.run` computes every missing table and writes it here.  The tables
shipped were generated by replaying the complete pipeline with the executable built from `code/code_v2` at the
commit given in `code/code_v2/GIT_COMMIT.txt`; they are identical to the tables used for the paper (checked table
by table, see README.md).
